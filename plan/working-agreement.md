# Как мы работаем

## Разделение труда

| Кто | Что делает | Что не делает |
|-----|------------|---------------|
| **Ты** | Код продукта (`apps/`, тесты, конфиги рантайма), клики в GitHub UI (Project, PR, merge), разбор конфликтов руками | Не обязан писать `plan/`, rules, промпты и «память» для ИИ |
| **Ассистент** | `plan/**`, ADR-черновики по твоей развилке, sessions, backlog-зеркало, startprompt, `.cursor/rules` — всё, что нужно ИИ помнить контекст | Не пишет за тебя прикладной код, пока ты явно не попросишь точечную помощь / пример |

Роль ассистента по коду: **старший товарищ** — направление, критерии готовности, риски, альтернативы, разбор ошибок. Теория точечно под блокер (~25% / 75% практики).

## GitHub Project — источник правды по статусу

Project: [DPLine Flow](https://github.com/users/skv0r/projects/1)

| Слой | Где правда |
|------|------------|
| Статус / приоритет исполнения | GitHub Project (колонки IceBox → Ready → In Progress → Review → Done) |
| Формулировка задачи | GitHub Issue |
| Контекст фазы / продукта | `plan/roadmap.md`, `plan/main.md` |
| Опыт сессии (бухгалтерия памяти) | `plan/sessions/` |
| Краткое зеркало для ИИ | `plan/backlog.md` (обновляет ассистент **после** чтения Project) |

### Ритуал сессии (жёстко для агента)

1. **Старт:** прочитать GitHub Project + актуальные Issues → обновить локальные `plan/*.md` при расхождении → только потом код/помощь по коду.
2. **Работа:** одна задача = одна ветка от `dev` (см. ниже).
3. **Конец:** запись в `plan/sessions/` + статус на Project + **push обязателен**. Сессия без push не считается закрытой.

## Ветки

| Ветка | Смысл |
|-------|--------|
| `main` | Прод: стабильный продукт |
| `dev` | Рабочая сборка; сюда мержим завершённые задачи |
| `app-<номер><код>` | Продуктовая задача, напр. `app-13fr` (frontend), `app-11be` |
| `pr<номер><слово>` | Практика, напр. `pr16gitflow` |

Подзадачи при необходимости ветвятся **от ветки задачи**, не от `main`. На каждом уровне: PR → конфликты → merge → в итоге в `dev`.

Связь с issue: в PR указывать `Closes #N` / `Refs #N`.

Теория и разбор ошибок: [guides/git-flow.md](./guides/git-flow.md).

## Формат сессии

1. Цель одной фразой + номер issue / карточка Project.
2. Что сделал / где застрял (лог, файл, поведение).
3. Ассистент пишет/дополняет `plan/sessions/YYYY-MM-DD.md` (ты можешь поправить факты по времени и ощущениям).

## Ревью

После значимого куска кода — запрос ревью: границы, ошибки, безопасность, гонки. Позже: Bugbot на PR + `/review` до push. Замечания-повторялки — в backlog или чеклист перед коммитом.

## Документы (ADR)

Крупное решение (фреймворк, auth, деплой, пакетный менеджер) — короткий ADR в `plan/decisions/`. Черновик может набросать ассистент; выбор варианта и «приняли» — за тобой.

Теория: [guides/adr.md](./guides/adr.md). Шаблон файла: [decisions/README.md](./decisions/README.md).
